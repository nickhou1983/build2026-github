Agent 入口 · Entry Points— 03

三个入口,同一套 Agentic 运行时

无论从桌面、终端还是网页进入,身份、策略与审计保持一致——因为它们共享驱动 Copilot App 的同一个 agentic runtime。

Copilot App

Agent 原生桌面端。多 Agent 并行编排,隔离 worktree,Canvas 协作,云/本地沙盒。"My Work" 统一视图。

入口 ① Copilot App— 04

Agent 原生桌面端:多 Agent 编排中心

面向"并行指挥多个 Agent"而设计的桌面应用,把会话、issue、PR、后台自动化收进一个控制中心。面向 Pro / Pro+ / Business / Enterprise 技术预览。

并行会话 · 隔离 worktree

每个会话跑在独立 git worktree,互不干扰;App 自动建立与清理,无需手动切分支。

Canvas 双向工作面

Agent 实时更新计划、diff、浏览器、部署状态;人可在同一表面编辑、重排、改向。

云 / 本地沙盒

Agent 在受控环境跑代码、看结果、迭代,不触碰生产;组织自定义策略。

会话模式

Interactive 协作 · Plan 先审计划 · Autopilot 全自主。随时可切换。

来源:GitHub Blog《The agent-native desktop experience》· GitHub DocsTechnical Preview
入口 ② Copilot CLI— 05

终端里的 Agent,更安全的"狂野西部"

从代码补全进化为 agent-loop 执行:规划、直接改文件、多步任务。也是驱动 Copilot App 的同一套运行时。

Plan Mode（Shift+Tab）

动手前先暂停:分析工作区、追问澄清、给出分步计划,遏制幻觉,让 CLI 在生产环境更可靠。

Agentic Memory

记住团队规约(如"始终用 Zod 校验"),永久保存;像从第一天就懂你惯例的资深搭档。

语音输入 · /every

设备端语音转写,音频不出本机;/every 调度周期性重复任务。

MXC 沙盒隔离

进程级隔离,与 OpenClaw 同源的策略驱动容器,限定 Agent 运行时可访问的资源。

来源:GitHub Blog · Microsoft DevBlogs · Microsoft Build 2026 Recap同一 Agentic Runtime
入口 ③ GitHub.com— 06

网页即 Agent 界面 + 治理中枢

把 issue 指派给 Copilot coding agent 就能直出 PR;而 Agent HQ / AI Controls 让企业把所有 Agent 活动纳入统一、可审计的视图。

Issue → PR

在网页上把 issue 指派给 coding agent,后台产出改动并开 PR,可在浏览器直接评审。

Agent HQ · AI Controls

"Mission Control":统一视图杜绝 Shadow AI,专设 AI 管理员角色,全量审计会话活动。

自定义 Agent · 版本控制

企业规范写入 .github/agents/*.md,push rule 保护路径,策略跨企业强制执行。

MCP 注册表 / allowlist

中心化控制 Agent 可连接的外部工具与数据源,敏感数据不出内网。

核心能力 ① Agent Sandbox— 07

隔离执行环境:让 Agent 安全地动手

当 Agent 越来越多地代你跑命令、改文件,沙盒提供隔离、可移植与策略控制。公开预览。

Local Sandbox

在你自己机器上运行,限制文件系统 / 网络 / 系统能力。/sandbox enable 开启;含在 Copilot 席位内免费;可经 Intune / MDM 集中管控。

macOS · Linux

Cloud Sandbox

GitHub 托管、完全隔离的临时 Linux 环境,构建于 Azure Container Apps Sandboxes。copilot --cloud 或在 App 新建会话时选择;跨设备续接;按用量计费。

Ephemeral · Hosted
  • 会话生命周期:Active(运行)→ Stopped(快照保存,可恢复)→ Deleted(环境+快照清除)
  • 前置策略:组织 / 企业所有者须先启用 Cloud Sandbox access,成员方可使用

核心能力 ② Agentic Workflows— 08

用 Markdown 写仓库自动化,而非 YAML

自然语言描述目标,AI Agent 在 GitHub Actions 里解读并执行。gh aw compile 编译成标准 Actions;增强而非取代确定性 CI/CD。公开预览。

自然语言优先

写"想要什么",Agent 想"怎么做"。默认 Copilot CLI,也支持 Claude / Codex / Gemini。

Security-First

默认只读 + Safe Outputs 兜底、沙盒执行、网络隔离、SHA 锁定依赖、用 GITHUB_TOKEN。

灵活触发

事件 / 定时 / 手动 / 评论命令。可 paths: 过滤降噪,max-ai-credits 控预算。

  • 典型场景:issue 三分类 · CI 失败归因 · 文档维护 · 测试覆盖率 · 合规巡检 · 仓库健康报告
  • 判断力分界:需"读懂并判断"的柔性任务用它;精确可复现的构建/发布仍用传统 Actions

核心能力 ③ Copilot Code Review— 09

让审查深度匹配改动复杂度

自动化 PR 评审,按改动复杂度分级路由,把算力花在刀刃上。中阶(Medium)公开预览。

Low(默认)

快速、成本高效。适合文档、小仓库、直白改动。常规模型,基础检查。

Fast · 默认

Medium(中阶 · 新)

路由到 higher-reasoning 模型,深挖复杂逻辑、安全敏感代码、跨服务改动。更多可执行建议、更少误报、抓微妙 bug。

更多 AI Credits
  • 带入团队上下文:Agent Skills(.github/skills)+ MCP 把 diff 之外的规范与系统接入评审;含 /security-review
  • 配置与可见性:组织级默认 + 逐仓库覆盖;Medium 归因标签;CLI 化文件工具让成本再降约 20%

核心能力 ④ Agent Merge— 10

自动接管 PR 的"最后一公里"

把已开好的 PR 一路推过评审、检查、修复直至合并——盯 CI、追 reviewer、修失败检查,条件齐了才动手。

持续闭环 · 后台运行

监控 CI、跟踪必需 reviewer、修复失败检查,迭代到全绿。后台运行、重启存活、合并后自动关闭。

分级自主 · 你定边界

① 仅把 CI 拉回绿 · ② 额外回应评审 · ③ 条件满足即合并。"你决定 Copilot 走多远、什么东西上线。"

  • 绝不越界:只在 "as soon as GitHub allows" 时合并,严守 branch protection;隔离 worktree 并行
  • 可审计可度量:动作带 actor_is_agent;Copilot 审并合的 PR 指标纳入 Usage Metrics API
