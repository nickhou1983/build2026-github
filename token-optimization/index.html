UBB 的本质不是让 Copilot 变贵，而是把提示词、上下文、输出、工具和模型选择这些工程决策变成可度量成本。

90%+

4×–8×

5–25×

-72%

真实案例中，MCP 工具从 188 个降到 52 个，每个 Agent 任务节省约 1.3 万 token。

基础：Token 到底是怎么工作的

建立共同语言

在讨论优化之前，先理解 token、上下文窗口、输入输出价格差异三个基本概念。

  • Token 不是字符，也不是单词
  • 上下文窗口里真正昂贵的是隐藏输入
  • 输出 token 通常比输入 token 贵 4×–8×
背景 · Slide 03

6 月 1 日的转折点

用量计费改变了游戏规则

用户输入只是水面上的一小块，系统提示词、仓库指令、文件上下文、对话历史和工具 Schema 才是成本主体。

  • 每次提示、工具调用、Agent 步骤都会形成可量化账单
  • 隐藏结构性开销通常占一次请求的 90% 以上
  • 优化重点应从“少打字”转向“缩小整座上下文冰山”
基础 · Slide 04

什么是 Token？

BPE 子词：既不是字符，也不是单词

现代 LLM 使用 Byte Pair Encoding 切分文本；短文本不一定便宜，真正关键是表达密度。

  • 常见英文词经常是单 token
  • 复杂词会拆成多个子词
  • 结构化、代码化表达通常比散文更省 token
成本结构 · Slide 05

Token 都去哪了

上下文窗口的冰山

一次看似很短的输入，会叠加系统提示词、指令文件、文件上下文、历史消息与工具定义。

  • 输入 20 个字符可能触发 2,000+ token
  • Agent 会话累积 5 万 token 很常见
  • 长期对话、工具 Schema 和上下文重载会相互放大
经济性 · Slide 06

贵的是输出

各家厂商普遍 4×–8×

输出价格显著高于输入，控制回复长度是 ROI 最高的优化动作之一。

  • GPT-5 mini 输出约为输入 8×
  • GPT-5.4 / Gemini 3.1 Pro 约为 6×
  • 一条输出格式约束可持续降低 40–70% 输出成本

平台侧的 6 类优化

Copilot 通过缓存、延迟加载、后台小模型、增量传输等方式降低主模型 token 消耗。

  • Tool Search 延迟加载减少工具 Schema
  • Agentic Search / Execution 把搜索与终端执行卸载给小模型

杠杆 1 · Slide 09

杠杆 1：提示词压缩

扔掉脚手架

删除客套和零信息量词，保留技术细节；输入和输出压缩是两个独立旋钮。

  • 礼貌请求可压缩为直接指令
  • Lite / Full / Ultra 三档对应不同歧义风险
  • 默认建议采用 Full：30–50% 输入节省，40–55% 输出节省
杠杆 1 续 · Slide 10

结构化与代码原生表达

同一任务，选择更便宜的表达

伪代码、类型签名、“像 X 但要 Y”等表达通常比自然语言更短，模型理解效果相近。

  • REST API 需求从散文改为结构化可省约 36%
  • 自然语言、伪代码、类型签名、类比式表达成本依次降低
  • 声明式规则比命令式步骤更容易叠加
杠杆 2 · Slide 11

杠杆 2：语言税

为什么英文最划算

对 Copilot 中主流 LLM 而言，英文通常是最便宜的提示词语言；中文接近英文，但不同厂商差异明显。

  • 非英文平均成本：Gemini / Qwen 较低，Anthropic 较高
  • 中文平均接近英文，约 1.02×
  • 代码相关提示优先用英文，避免不必要翻译
杠杆 3 · Slide 12

杠杆 3：上下文管理

缩小永远会被加载的部分

把规则拆成常驻、条件加载、按需三层，并用 applyTo 限定范围，避免每轮加载全量 wiki。

  • 常驻规则只保留风格、命名、输出限制
  • API / 数据库 / 模块规则用路径匹配条件加载
  • PR 清单、调试手册、迁移手册改为按需调用
杠杆 4 · Slide 13

杠杆 4：输出控制

ROI 最高的一条指令

在 copilot-instructions.md 中设置输出上限，可永久压缩高价输出 token。

  • Code only, no explanation 可省 60–80%
  • Yes or no, then one line why 可省 70–90%
  • 需要学习或排查时再显式要求解释
杠杆 5 · Slide 14

杠杆 5：工作流模式

Ask、Plan、Agent

用最便宜且能完成任务的模式；模糊提示直接跑 Agent 是最烧钱的反模式。

  • Ask：单次调用，适合提问和解释
  • Plan：单次调用，适合方案设计
  • Agent：多步调用，适合多文件重构和端到端实现
杠杆 6 · Slide 15

杠杆 6：模型路由与推理强度

让贵模型负责想，便宜模型负责敲字

混合路由通常比单一模型策略省 25–55%，尤其适合规划与执行分离的工作流。

  • GPT mini / Auto：语法、API 查询、一次性问题
  • Sonnet：日常实现与重构主力
  • Opus：架构、安全审计、复杂新问题
杠杆 7 · Slide 16

杠杆 7：AGENTS.md

保留地雷，删除噪声

AGENTS.md 应记录代码无法推断的约束，而不是成为项目 wiki；噪声会增加成本甚至降低正确率。

  • 保留：Use uv, not pip；Deploy needs VPN；Do not refactor auth
  • 删除：This is a Python project；Tests live in tests/
  • 把指令文件当作 bug 追踪器，而不是百科全书
杠杆 8 · Slide 17

杠杆 8：MCP 工具 Schema 税

每个启用工具都会在每一步重发

MCP 工具越多，Agent 步数越多，Schema 重载成本越高；应按工作区配置而非全局启用。

  • 188 个工具跑 30 步可带来约 330K token
  • 真实盘点从 188 个工具降到 52 个，减少 72%
  • 任务不需要的 MCP 服务器就关闭
收束 · Slide 18

行动清单与结语

UBB 没有让 Copilot 变贵，只是让“不动脑子”变贵了

7 步行动清单中，压缩指令、禁用无用 MCP、添加 applyTo 收益最大；Token 优化同时提升成本效率与模型注意力。

  • 10 分钟压缩 copilot-instructions.md
  • 15 分钟盘点 MCP 与 applyTo 指令文件
  • 每月做一次配置回顾，让节省变成团队习惯
