Agentic Harness 设计详解

"模型供智能，Harness 供代理力" — Copilot SDK 单一共享内核驱动 CLI / App / Code Review / VS Code
🔧 核心设计：三大职责 + Agent Loop
  • 上下文组装 — system prompt、工作区结构、多轮历史、工具结果、跨会话记忆；"模型看到什么"由 Harness 决定
  • 工具暴露与执行 — JSON Schema 声明工具，校验参数→执行→回填结果；MCP / 扩展可注入新工具
  • Agent Loop — think→act→observe 循环：每轮重建 prompt、tool-call 上限、stop hooks、超长历史自动摘要压缩
  • 按模型定制 — 每模型独立 system prompt / 工具集（Claude 用 replace_string，GPT 用 apply_patch）
📊 多模型架构 + 评测体系
  • 20+ 模型 + BYOK — Auto 模型选择按任务意图与模型健康度自动挑选，任选效率或峰值质量
  • 跨模型能力 — Rubber Duck 跨模型家族互评，单一厂商 Harness 无法实现
  • 基准对标 — SWE-bench V/Pro · SkillsBench · TerminalBench · Win-Hill：解决率与 Claude Code / Codex CLI 持平，多数配置更省 Token
  • 评测门禁 — 动到工具 / prompt / loop 的 PR 自动跑 benchmark 后才可合并（VSC-Bench）
🏎️ "模型是引擎，Harness 是整车" — 上下文、工具、循环与评测才是 Copilot 工程主战场

/fleet 多 Agent 编排详解

编排器像项目负责人一样分工：分解 → 并行派发 → 验证汇总
⚙️ 工作原理（5 步）
  • 分解任务 — 拆为带依赖关系的独立工作项
  • 识别并行性 — 无依赖项并行，有依赖项串行
  • 派发子 Agent — 各自独立上下文，共享文件系统
  • 轮询进度 — 完成后派发下一波任务
  • 验证汇总 — 校验输出并合成最终交付物
🎯 使用要点与注意
  • 明确交付物 — 每项对应具体文件，模糊 prompt 退化为串行
  • 声明依赖与边界 — 指定目录归属、禁改范围、验证标准
  • 自定义 Agent — .github/agents/ 定义专职 Agent，按任务配模型
  • ⚠️ 无文件锁 — 多 Agent 写同一文件会静默覆盖，须分区
  • ⚠️ 上下文自包含 — 子 Agent 看不到编排器会话历史
💡 适合多文件重构、批量文档、API+UI+测试并行；线性单文件任务不划算 · /tasks 查看运行中的子 Agent

Ruleset = 约束 三层叠加

状态检查的本质 两大陷阱

Ruleset 只强制"名为 X 的检查必须绿"，检查内容由 workflow / CI 定义；注意 context 名字须完全匹配、skipped 计为 Success

Bypass 治理 能力边界

直接绕过（bypass actor）vs 委派审批（bypass request）；GitHub App 可作 bypass actor、可只读监控，但不能审批请求
