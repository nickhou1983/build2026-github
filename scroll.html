架构收敛：一个 Agent 内核，多个表面

Copilot SDK / CLI 成为统一运行时 — App、VS Code、JetBrains 均为其"显示与控制层"

🧠 统一运行时的官方证据
  • Copilot App — 构建于 CLI 之上：Business/Enterprise 须启用 CLI 策略；CLI 会话直接进入 My Work 视图
  • VS Code Agent Host — Copilot harness 由 Copilot SDK 驱动，官方明确"行为与 CLI / App 对齐"
  • JetBrains IDEs — 内嵌 Copilot CLI + Agent Picker + Slash Commands
  • Windows Terminal — Copilot CLI 作为默认 Agent 体验
  • Copilot SDK — 暴露的正是驱动 Cloud Agent 与 CLI 的同一套生产级 runtime
🔌 VS Code AHP 架构要点
  • Agent Host 独立进程承载会话，通过开放协议 AHP（JSON-RPC + 不可变状态/纯 reducer）与编辑器通信
  • 会话与窗口解耦 — 关窗口任务照跑，多窗口可连同一会话实时同步
  • 远程执行 — code agent host + SSH / dev tunnel，UI 在本地、执行在代码旁
  • 多 harness 插拔 — Copilot / Claude / Codex 统一接入，均支持 worktree 隔离
  • 客户端贡献工具 — 浏览器/扩展工具注册进会话，调用路由回贡献方
💡 一次发布，处处可用：功能做在 runtime 层（Rubber Duck / chronicle / 沙箱 / 语音），各表面只需接入 — AHP 之于 Agent，如同 LSP 之于语言服务器

Agentic Harness 设计详解

"模型供智能，Harness 供代理力" — Copilot SDK 单一共享内核驱动 CLI / App / Code Review / VS Code

🔧 核心设计：三大职责 + Agent Loop
  • 上下文组装 — system prompt、工作区结构、多轮历史、工具结果、跨会话记忆；"模型看到什么"由 Harness 决定
  • 工具暴露与执行 — JSON Schema 声明工具，校验参数→执行→回填结果；MCP / 扩展可注入新工具
  • Agent Loop — think→act→observe 循环：每轮重建 prompt、tool-call 上限、stop hooks、超长历史自动摘要压缩
  • 按模型定制 — 每个模型独立 system prompt / 工具集（Claude 用 replace_string，GPT 用 apply_patch）
📊 多模型架构 + 评测体系
  • 20+ 模型 + BYOK — Auto 模型选择按任务意图与模型健康度自动挑选，任选效率或峰值质量
  • 跨模型能力 — Rubber Duck 跨模型家族互评，单一厂商 Harness 无法实现
  • 基准对标 — SWE-bench V/Pro · SkillsBench · TerminalBench · Win-Hill：解决率与 Claude Code / Codex CLI 持平，多数配置更省 Token
  • 评测门禁 — 动到工具 / prompt / loop 的 PR 自动跑 benchmark 后才可合并（VSC-Bench）
🏎️ "模型是引擎，Harness 是整车" — 上下文、工具、循环与评测才是 Copilot 工程主战场

/fleet 多 Agent 编排详解

编排器像项目负责人一样分工：分解 → 并行派发 → 验证汇总

⚙️ 工作原理（5 步）
  • 分解任务 — 拆为带依赖关系的独立工作项
  • 识别并行性 — 无依赖项并行，有依赖项串行
  • 派发子 Agent — 各自独立上下文，共享文件系统
  • 轮询进度 — 完成后派发下一波任务
  • 验证汇总 — 校验输出并合成最终交付物
🎯 使用要点与注意
  • 明确交付物 — 每项对应具体文件，模糊 prompt 退化为串行
  • 声明依赖与边界 — 指定目录归属、禁改范围、验证标准
  • 自定义 Agent — .github/agents/ 定义专职 Agent，按任务配模型
  • ⚠️ 无文件锁 — 多 Agent 写同一文件会静默覆盖，须分区
  • ⚠️ 上下文自包含 — 子 Agent 看不到编排器会话历史
💡 适合多文件重构、批量文档、API+UI+测试并行；线性单文件任务不划算 · /tasks 查看运行中的子 Agent
02 · DEEP DIVE

Rubber Duck & Security Review Agent

质量与安全双守门员 — 跨模型评审 + 预提交漏洞扫描

🦆 Rubber Duck（GA）
  • 跨模型评审 — 刻意用不同模型家族做批评家（Claude 主会话 ↔ GPT 评审），规避同源盲区
  • 高杠杆时机自动咨询 — 规划后实现前、复杂实现中途、写完测试后、反复失败时
  • 只报真问题 — bug / 逻辑错误 / 设计缺陷 / 性能瓶颈，不评论风格与命名
  • 分级反馈 — Blocking / Non-blocking / Suggestions，附具体修复建议
  • 只读权限 — 不改文件，采纳与否由主 Agent 决定；/rubber-duck 可手动调用
🔒 Security Review（公开预览）
  • 预提交扫描 — /security-review 对本地 diff 做 LLM 上下文推理，代码进 PR/CI 前发现漏洞
  • 覆盖 11 类高危漏洞 — SQLi / XSS / SSRF / 越权 / 弱加密 / 硬编码凭据 / 供应链 / XPIA 跨提示注入
  • 高置信度过滤 — 每条附严重度 + 置信度 + 修复建议，降低误报噪音
  • 轻量补充 — 独立于 code scanning / Dependabot / secret scanning，可配合 GitHub MCP 调用真实扫描
  • 多端可用 — Copilot CLI（实验模式）与 Copilot App，全计划开放
🎯 组合拳：Rubber Duck 把关计划与实现质量 · Security Review 把关安全 — AI 写的代码由 AI 先自查
